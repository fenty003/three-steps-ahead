# Three Steps Ahead · 意图回读

> 让 AI 在动手之前，先用四张卡确认「你要的」「我要做的」「预期结果」「补充说明」。

一个纯提示词的 Agent Skill。没有脚本、没有依赖、不联网，`SKILL.md` 可以直接通读审计。

名字取自万智牌同名瞬间牌 [`Three Steps Ahead`](https://scryfall.com/card/otj/75/three-steps-ahead)（Outlaws of Thunder Junction，OTJ #75）——那张牌本身就是"基础费用 + 三档自选"的 Spree 结构，和这里的四张卡是一回事。详见[名字与致敬](#名字与致敬)。

## 它解决什么

AI 最常见的失败不是"不会做"，而是"做错了方向还很努力"：你说"帮我把导出弄好"，它理解了三种可能的"弄好"，挑了一个，做完你才发现不是那个。

回读要做的事只有一件：**在它开始动手之前，把你脑子里的那个东西再说一遍给你听，让你有机会点个"不对"。**

现在纠正只要一次点击；等它干完再纠正，往往要返工半天。

## 它长什么样

你发：

```text
帮我改导出，^Excel 打开时中文不能乱码，别的都不用动^，改完我自己验。
```

它不发车，先弹四张确认卡（1/4 → 4/4）：

| # | 卡片 | 内容 | 选项 |
| --- | --- | --- | --- |
| 1/4 | 你要的 | 我理解你要的是：导出的 Excel 用 Excel 打开时中文不乱码 | 对 / 不对，我改 |
| 2/4 | 我要做的 | 我接下来要做的是：定位导出环节的编码处理，改成带 BOM 的 UTF-8，再重新导出验证一次 | 对 / 不对，我改 |
| 3/4 | 预期结果 | 做完你会看到：你重新导出并打开，中文正常；我给出改动的文件和位置 | 对 / 不对，我改 |
| 4/4 | 补充说明 | 还有什么要补的？（限制条件／别动的东西／参考样例） | 没有补充 / 我要补一句 |

你确认完，它**直接开工**，不会再问"可以开始了吗"。

## 触发方式

用两个脱字符把要回读的段落**框起来**，开闭同形：

| 你发什么 | 会发生什么 |
| --- | --- |
| `^^这段话我描述得不清^^` | 这一段出四张卡 → 你点完 → 开工 |
| `^^第一段^^ 中间随便写 ^^第二段^^` | 两段各一组四张卡，逐段确认 |
| 说"先复述一下我的需求""回读一下" | 把整条消息当一段处理 |
| 没有 `^^` | 不打扰，直接干活 |

**为什么是 `^^` 而不是 `？？`。** 早先版本用开头 `？？` 当开关，但中文里"？？"本身就是表达困惑的常用打法，会天天误触发。`^^` 在中文正文里几乎不出现、键盘 Shift+6 两下就能打、也不撞任何 markdown 语法（`##`、`~~`、`**` 这些会被渲染吃掉）。全角 `＾＾` 一样认，中文输入法怎么出都行。

**奇数个 `^^` 不猜。** 只开不闭的时候，它会先问一句这段到哪结束，再出卡。

**不支持嵌套。** `^^外层 ^^内层^^ ^^` 会被拆成两段；要分层就分开发消息。

唯一的例外：没有 `^^`、但某个动作有副作用且存在两种以上合理解读时，会问 1 个问题再动，而不是猜着做。

## 安装

### DeepSeek Harness

用户级（所有项目可用）：

```bash
mkdir -p ~/.dsh/skills/three-steps-ahead
cp SKILL.md ~/.dsh/skills/three-steps-ahead/SKILL.md
```

Windows PowerShell：

```powershell
New-Item -ItemType Directory -Force "$env:USERPROFILE\.dsh\skills\three-steps-ahead" | Out-Null
Copy-Item .\SKILL.md "$env:USERPROFILE\.dsh\skills\three-steps-ahead\SKILL.md"
```

项目级则放到 `<项目>/.dsh/skills/three-steps-ahead/`。放好后新开对话，技能清单里应出现 `three-steps-ahead`。

### Claude Code / Cursor / Codex 等

```bash
mkdir -p ~/.agents/skills/three-steps-ahead
cp SKILL.md ~/.agents/skills/three-steps-ahead/SKILL.md
```

Claude Code 也认 `~/.claude/skills/three-steps-ahead/`。

### 可选：让它每次对话都在场

Skill 是由模型按描述自行挑选加载的，可能这一轮就没加载。要更确定，把下面这段放进常驻指令文件（DSH 用 `~/.dsh/AGENTS.md`，其他工具用各自的 `AGENTS.md`）。**不要贴 `SKILL.md` 全文**，贴这份压缩版即可：

```markdown
## 意图回读

用户消息以两个问号开头时（`??` 或全角 `？？`），先用提问卡片确认四件事，再动手：
1. 你要的——我理解你要的是：<目的，一句话>
2. 我要做的——我接下来要做的是：<动作，动词开头、可数>
3. 预期结果——做完你会看到：<可验证的结果>
4. 补充说明——还有什么要补的？（限制条件／别动的东西／参考样例）

四张卡一次发出；收齐后直接开工，不要再来一轮"请确认"。第四张卡里用户写的补充内容直接采用。
宿主没有提问工具时，降级为四行文字回读并直接执行，并说明降级了。
确认理解不是执行授权：删除、覆盖、付费、对外发送、公开发布仍需单独确认。
```

## 设计取舍

**为什么是四张卡，不是一张。** 一张卡只能确认"我理解对吗"，用户说"不对"之后你还得问哪里不对。字段拆开后，错在哪一格可以直接定位、直接改。

**为什么第四张不预设内容。** 前三张都是我写的，第四张是留给用户的缺口：临时想起来的限制、不能碰的东西、参考样例。如果我往里塞自己的需求，就等于把用户的口子堵上了。

**为什么点完就开工。** 回读是省时间的工具，不是审批流程。如果确认完还要再确认，它就从"省一次返工"变成"每次多花三下点击"，最后没人会用。

**为什么承认降级。** 不是所有宿主都有结构化提问工具。没有的时候退回四行文字并明说，而不是假装问过。

**为什么改成框段，而不是开头开关。** 长任务里常常只有中间某几段说不清，整条回读既浪费又不对焦；框段让用户自己划定范围，一条消息里还能框好几处。

## 已知限制

- 依赖宿主的结构化提问工具（一次调用发四个问题）。没有就降级为文字。
- **框几段就是几轮**：每段独立一组四张卡，框 3 段 = 3 轮共 12 张。这是刻意取舍：逐段确认最精确，但慢；嫌慢就少框几段。
- 超过 4 段时会先问一句要不要合并或分批，不会闷头连问十几张。
- 卡片会阻塞一次交互，四张卡就是四次点击。
- 不同宿主对卡片正文的渲染不一（换行、加粗、长度），所以正文限死一句话。
- 这是工作流约定，不是强制拦截器，无法覆盖宿主的更高优先级规则和权限限制。

## 名字与致敬

万智牌《Outlaws of Thunder Junction》的蓝色瞬间 [`Three Steps Ahead`](https://scryfall.com/card/otj/75/three-steps-ahead)（OTJ #75，Rare，Artist: Francisco Miyara）是一张 **Spree** 牌：付 `{U}` 基础费用，然后按需加选三档之一或多项——`+{1}{U}` 反击目标咒语、`+{3}` 复制你操控的神器或生物、`+{2}` 抓两张牌再弃一张。

| 那张牌 | 这个技能 |
| --- | --- |
| 基础费用 `{U}`：选什么都得先付 | 不管请求大小，先回读一次再动手 |
| Spree：选一项或多项，由出牌的人决定 | 四张卡由用户逐项确认，第四张可选 |
| 三个自选档 | 「你要的」「我要做的」「预期结果」 |
| 风味文字大意：她为每一种可能都做了准备，唯独没准备失败 | 回读就是为了别在开头埋下"没准备失败"这种结局 |

本项目只借名字和结构，**不包含任何卡片图像、官方美术或完整牌面文本**。Magic: The Gathering 及相关名称是 Wizards of the Coast 的商标与版权财产，本项目与 Wizards of the Coast 无关，也未获其背书。
